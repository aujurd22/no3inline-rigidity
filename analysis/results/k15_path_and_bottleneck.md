## 1. 统一引理已可操作化（下游预筛就绪）

`implication_kernel_unified_lemma.md` 证明了：k=14 的全部 23 个补全因子（全体，非抽样）的
无解性纯由一元+二元约束解释，且矛盾核在「重命名+翻转」正规化下塌缩为**单一 2-变量 3-边
奇异蕴含环**（canonical `((0,0,0,1),(0,1,1,0),(1,0,0,0))`）。

`scc_prescreen.py` 把该引理做成可复用工具：给定一幅 k-替换补全（37 条边），只取一元/二元约束
建 2-CNF 蕴含图 → Tarjan SCC 判定矛盾。
- **sound**：2-SAT 是原命题的松弛，SCC UNSAT ⇒ 真 UNSAT（无假阴性）。
- **k=14 上 complete**：23/23 UNSAT 全由 2-SAT 解释，无需三元约束。
- 已交叉验证：在 `all_completions_kernelized.json` 上重算，23/23 UNSAT、类型数=1、与暴力 2^14 oracle 零不一致。

## 2. k=15 的真实瓶颈在管线最上游（不在取向判定）

k=15 全搜索管线的 stages：

```
[S1] CUDA 根候选扫描 (SURVIVOR_CAPACITY=300M)  →  幸存掩码
[S2] chunked 审计 q=0..q=3 (C++ v9 模式3 f-factor DFS)  →  q3 可行掩码
[S3] v9w_all 枚举每个 q3 掩码的补全因子
[S4] 取向判定：2^W 暴力 oracle  ← 或 SCC 预筛（本引理）
```

- **[S4] 不贵**：2^15 = 32768，CPU 即可；SCC 预筛更是线性时间。这是统一引理的作用点。
- **[S1] 才是瓶颈**：k≥15 时根候选数 ~1.8e9 > 300M，CUDA 缓冲 `SURVIVOR_CAPACITY` 溢出，
  `survivor_masks_complete=false`，拿不到 k=15 掩码。RTX 4070 12GB 路线上限已到顶。
- 结论：**统一引理解决的是下游 [S4]，但 k=15 卡在上游 [S1]。要拿到 k=15 掩码，必须先把 [S1] 拆开。**

## 3. 拿到 k=15 掩码的两条路径

### 路径 A：结构化超集探针（廉价，已启动，本 turn）
- 用 19 个 k=14 q3 幸存 mask，每个再删 1 个旧 cell（置位 1 个清零位），构造 **437 个 k=15 候选**
  （每盆地：01:69 / 02:92 / 03:138 / 04:92 / 05:46 / 06:0）。
- 直接喂 `audit_v20_k14_chunked.py --size 15 --max-q 3`（[S2]，已验证的 C++ 模式3），
  跳过 [S1] 的 CUDA 扫描（把 437 掩码写成假 GPU JSON 直接消费）。
- 对 q3 可行掩码跑 v9w_all（[S3]）+ scc_prescreen（[S4]），聚合逻辑类型。
- **价值**：用真实 k=15 实例检验「统一引理能否推广到 k=15」——若全部仍塌缩为同一 2-变量环
  → 引理推广成立（强证据）；若涌现新类型（更长环/三元耦合）→ 引理在 k=15 失效，转全局理论。
- **局限**：仅覆盖「含 k=14 幸存结构的」k=15 子集，不能证 k=15 全局封闭。

### 路径 B：k=15 完整搜索（多趟 CUDA 预筛，待授权）
- 既定方案（见 2026-07-20 记忆）：改 NVRTC-JIT 预筛 kernel/exe，按掩码前缀把 ~1.8e9 根候选
  拆成每趟 ≤300M 的多趟 GPU 扫描，合并幸存者。GPU 时间免费。
- 需重编 `v20_gpu_mask_prefilter.exe`（host C++ 链 cuda.lib/nvrtc.lib；nvcc 不可用）。
- 之后复用 `audit_v20_k14_chunked.py --size 15`（仅改参数）+ `collect_k15.py`（已写好）。
- **这是唯一能证 k=15 全局封闭的路径**，但需一次 CUDA 工程投入。

## 5. 决策点（据探针结果，2026-07-20）

- **路径 A 结论：引理推广成立（单一类型）。** k=14（已认证，23/23）+ k=15（探针，16/16）两档都塌缩为同一 2-变量奇异矛盾环，强烈暗示 V20 六盆地对局部 k-替换具**局部刚性**：任何小扰动都触发同一旧骨架→新边二元冲突。
- **不声称 k=15 封闭**：探针仅覆盖「k=14 幸存掩码的超集」这一结构化子集（15/437 掩码），未枚举 k=15 全空间（~1.8e9 被 CUDA 300M 瓶颈阻断）。**不得下「k=15 距离 ≥16」之类的全局结论。**
- **论证重心转向全局理论（优先级 ④）**：既然 k=14、k=15 两档局部替换都被同一矛盾环封死，继续逐 k 穷举性价比极低；更可能的是 m=37 若存在必为全新全局构造（全局 C4 容器 / 零进位理论），而非对 V20 盆地的局部修补。
- **路径 B（多趟 CUDA 重编）的性价比重估**：若目标只是「再证 k=15 全 UNSAT」，现在探针已给出强证据，投入 CUDA 工程的绝对值下降；除非要彻底封死 k=15（完整证书）或推进 k=16+，否则建议暂缓，先把精力放在全局理论上。是否启动路径 B 仍取决于用户是否授权 CUDA 多趟预筛重编。
