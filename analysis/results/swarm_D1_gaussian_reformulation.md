## 1. The geometric reformulation

Let `n = 2m = 74`, coordinates `(x,y) ∈ {0,…,n−1}²`.  The C4 lift of a cell
`(x,y)` is obtained by the rotation `ρ : (x,y) ↦ (n−1−y, x)`.

Shift the origin to the board centre `c = (n−1)/2 = 36.5` and **double** to
clear the half-integer:

```
a = 2x − (n−1) = 2x − 73,      b = 2y − (n−1) = 2y − 73        (a,b are ODD integers, |a|,|b| ≤ 73)
```

In these **centred-doubled** coordinates the rotation is exactly linear:

```
ρ_centred(a,b) = (−b, a)   ← a 90° rotation R with  R² = −I,  R⁴ = I.
```

Hence the four lifts of a cell `(x,y)` are precisely

```
{ Rᵏ(a,b) : k = 0,1,2,3 }  =  { (a,b), (−b,a), (−a,−b), (b,−a) } .
```

**Gaussian-integer form.**  Identify `(a,b) ↦ z = a + b·i ∈ ℤ[i]`.  Rotation is
multiplication by `i` (`i·(a+bi) = −b + ai`).  So the four lifts of cell `e` are

```
{ z_e · ω : ω ∈ μ₄ = {1, i, −1, −i} } .
```

This is the exact rot4-NTIL analogue of the CDCC construction's `μ`-orbit idea:
every cell contributes a *4th-root orbit* under the cyclic group generated by `i`.

**Validation (E1).**  On the best-known m=37 config the centred-doubled lift of
every cell, mapped back through `(a+73)/2`, equals the engine lift set with
**0 mismatches** across all 148 lifts.  The reformulation is exact.

## 2. Orientation as a *linear* mark in GF(p)  →  (X) is a quadratic Boolean system

For a fixed 2-factor edge `e = {u,v}` (stored `u ≤ v`) the two possible oriented
cells are `(u,v)` and `(v,u)`.  In centred-doubled coords the base vector is
`v_e = (α_e, β_e)` with `α_e = 2u−73, β_e = 2v−73` (fixed by the 2-factor).
Orientation is a binary mark `t_e ∈ {0,1}` selecting

```
M₀ = I ,    M₁ = σ = [[0,1],[1,0]]   (swap),
cell vector  w_e(t_e) = M_{t_e} · v_e .
```

The swap `σ` is a **linear** map over any field, so `w_e(t_e)` is *linear in the
mark* `t_e`.  The full lift set as a function of the orientation vector
`t = (t_1,…,t_m)` is therefore

```
S(t) = { Rᵏ · M_{t_e} · v_e  :  e = 1..m ,  k = 0..3 } .
```

Three lifts are collinear ⇔ the 3×3 determinant of their coordinates vanishes.
Each coordinate is linear in the relevant `t_e`, so **every collinearity
constraint is a quadratic polynomial in the binary marks** `t_e`.  Consequently:

> **Theorem (algebraic re-encoding).**  rot4-NTIL(m) exists ⇔ there is a 2-factor
> (giving base vectors `v_e`) and a bit-vector `t ∈ {0,1}^m` such that **none** of
> the `C(4m,3) = 547,340` quadratic determinant-polynomials over `𝔽₂` (or `𝔽_p`)
> vanishes.  The (X) objective is the number of these quadratics that evaluate to 0.

This is a clean, finite-field restatement of (X): a quadratic Boolean feasibility
system.  For a *fixed* 2-factor it collapses to a **quadratic unconstrained
Boolean optimisation (QUBO-style)** in only `m = 37` variables with a sparse
structured cost (each cubic term touches ≤ 3 variables — see §4).

## 3. Faithful prime-field embedding (R9a made explicit)

R9a (prior note) shows mod-`p` descent is valid only for `p > 2m` (else distinct
lifts can differ by `2m = 74` and coincide mod `p`).  We make the bound explicit.

For three points in `{0,…,n−1}²`, `|det| ≤ 3(n−1)² = 15987`.  Take any prime
`p > 15987` (we use `p = 15991`).  Then two distinct lifts never coincide mod `p`,
and `det = 0 in ℤ  ⇔  det ≡ 0 (mod p)`.  Hence over `𝔽_p`:

> **(X)  ⇔  "no three of the 4m lifts are collinear over 𝔽_p"**,  *exactly*.

So the whole problem is faithfully a system of `C(4m,3)` quadratic equations over
`𝔽_p`.  This is a rigorous algebraic encoding (not just a prune): a SAT/UNSAT
solver over `𝔽_p` on these equations, combined with the 2-factor (assignment)
constraints, decides existence.

**Validation (E2).**  Using `p = 15991`, the mod-`p` collinearity count equals
`Board.verify_total()` on the best-72 config (72 = 72) and on **6/6** random
configs (396, 440, 380, 316, 480, 384 — all exact matches).  The embedding is
correct and faithful.

*Note (R9a pitfall).*  Using `p = 37 = m` is **invalid**: lifts differ by 37 in a
coordinate and collapse mod 37, so a valid integer NTIL would be wrongly rejected.
The centred-doubled coordinates do **not** rescue this, because the doubled values
still span a 147-wide interval and collide mod 37.  Faithful embedding requires
`p > 2m`; the primality of `m = 37` is not what makes a field encoding work — the
large-prime bound does.  (The genuine algebraic leverage of m=37 being prime is the
Gaussian/μ₄ structure of §1, not a mod-37 descent.)

## 4. Structural finding from the best-72 config (E4)

For the deepest known local minimum (best_bad = 72, all 72 defects are size-3
triples), we decomposed each collinear triple by the number of *distinct edges*
whose lifts it contains:

```
two_edge_triples   = 0
three_edge_triples = 72
max edge involvement per defect = 16 ;  27 of 37 edges touch ≥1 defect
```

**Every residual violation involves lifts from exactly 3 distinct edges.**  So the
per-2-factor orientation conflict hypergraph (each forbidden collinearity = a
forbidden assignment of a subset of edge-orientation bits) is **3-uniform**: it is
a genuine 3-SAT-style CSP, not reducible to 2-SAT.  This explains *why* single
flips and even coordinated multi-flips stall at 72 (already observed) — resolving
any one triple forces a move on ≥ 2 of its 3 edges, and the constraints do not
decouple.  The orientation subproblem is inherently a 3-variable (quadratic)
constraint system, exactly matching the §2 polynomial description.

## 5. Status / what the algebraic encoding buys

* It gives a **single clean object**: a quadratic Boolean/𝔽_p system over `m`
  marks plus the 2-factor (permutation) constraints (the R9b assignment model).
  This is the precise algebraic counterpart of "find a 2-factor + orientation with
  no vanishing cubic determinant".
* It makes the per-2-factor orientation problem a **QUBO/3-SAT** in 37 vars —
  a natural target for a dedicated MaxSAT or Groebner attack over `𝔽_2`, which the
  general SA engine does not exploit.
* It is **faithful** (no false rejects) for `p > 2m`, so it can serve as an
  independent verifier distinct from the engine's pair-count.

No breakthrough (no total_bad = 0 config, no impossibility proof) was found; see
`swarm_D1_experiment.json` / `.md` for the search results.

**Next-step suggestion.**  Fix the best-72 2-factor (or several low-defect
2-factors) and attack the *orientation* subproblem directly as a MaxSAT / quadratic
Boolean problem over `𝔽_2` (37 vars, ~547k quadratic terms but 3-uniform sparse).
If a 2-factor exists whose orientation subproblem is SAT, we win; the 3-uniform
structure (§4) suggests a 3-SAT / CDCL solver is the right tool, complementing the
R9b permutation CSP.
