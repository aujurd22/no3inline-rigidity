## Independent checks

The verification parsed the 74 displayed database rows, formed all 148 points,
and canonicalized the integer line through each of the
`binom(148,2) = 10,878` point pairs.  The results were:

| check | result |
|---|---:|
| points | 148 |
| points per row | exactly 2 in all 74 rows |
| points per column | exactly 2 in all 74 columns |
| quarter-turn invariance `(x,y) -> (y,73-x)` | true |
| distinct canonical pair-lines | 10,878 |
| line occurring for more than one pair | 0 |

The last line is stronger than the needed pair-count test: if three selected
points were collinear, their common line would be generated by three different
pairs.  Therefore this is a valid C4-symmetric no-three-in-line configuration.

## Fundamental-domain signature

The northwest `37 x 37` fundamental square contains 37 cells.  As a 2-regular
pseudograph, their component lengths are

```text
31 + 5 + 1,
```

where the final component is the loop `(16,16)`.  This is compatible with the
repository's corrected loop/digon model and shows that neither a Hamiltonian
factor nor a loop-free factor can be imposed as a necessary condition.

The true oriented cell set shares only `(19,1)` and `(22,14)` with the
repository's score-60 incumbent.  The overlap remains 2 of 37 after forgetting
edge orientation, so the selected-cell deletion distance is 35.
This explains why exact local neighborhoods of the score-60 point did not
approach the solution.
