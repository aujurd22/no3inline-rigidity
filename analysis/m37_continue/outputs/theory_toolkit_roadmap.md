## 0. 当前状态速览

- m=37 仍是 OPEN：既未找到解（坏三元组=0），也未证明不存在。
- 已知最佳 2-因子（外部 agent 的 `joint_v14_*` 家族，9 个）在 **正确** oracle 下
  的精确最优值 = **56**，而非此前声称的 40。
- 旧 `enumerate_clauses` 共线 oracle 有 bug（每边只取 4 个 C4 提升点中的 2 个），
  导致所有依赖它的 SA / 旧 CP-SAT / "匹配壳层最低 56" 结论都建立在错误目标上。
- 外部 agent 已用正确的 `weighted_geometry_ising` 重跑，并自校验
  `assert weighted == geometric`。`weighted_geometry_results.json` 即其产物。
- `exact_factor_archive.json` 中的 `v40_01..04`（声称值 40）**尚未用正确 oracle 复核**。

## 1. 共线 oracle 的 bug 与修正（已确认）

| 对象 | 每边提升点数 | 是否含全部 4 个旋转点 | 状态 |
|------|------------|---------------------|------|
| `signed_nae_core.enumerate_clauses` | 2 | 否 | **BUG** — 35/44 违例是几何非共线假阳性 |
| `weighted_geometry_ising.enumerate_weighted` | 4（每取向）+ 4×4×4 枚举 | 是 | 正确，自带 `assert weighted == geometric` |

实证（v40_01 归档取向）：
- 真实几何坏三元组 `geometry_bad_count` = **40**
- 旧 clause 模型数出 44，其中 **35 个几何上不共线**（假阳性）
- 旧 CP-SAT "最优" 给 14（错）；SA 用坏 oracle 把 v40_01 优化成 56（严重低估）

**结论**：所有基于 `enumerate_clauses` 的经验墙都需重测。正确模型的"墙"目前已知
最低为 56（joint_v14 家族），但 v40 档案是否真有 40 仍在复核中。

## 2. 是否需要专门造数学工具？——是，首要目的是消灭这类 bug

当前代码是一堆互相重叠、各自实现共线判定的脚本，潜伏 bug 是必然。建议工具包：

| 模块 | 职责 | 防 bug 手段 |
|------|------|------------|
| `fd_model` | 2-因子↔边、取向比特、C4 提升（唯一实现） | 与暴力枚举对拍小 m |
| `collinearity` | **唯一**共线判定函数 | 每个 m 跑 `geometry_bad_count` 对拍 |
| `oracle` | 正确加权代价矩阵 J（缓存） | `assert weighted == geometric` |
| `optimizers` | CP-SAT 精确 + 在正确 J 上的局部搜索 | 与暴力对拍小 m |
| `analytics` | 圈分解、对称差、FD 向量、谱 | — |
| `property_tests` | 基于 hypothesis/对拍的属性测试 | 每次改动回归 |

## 3. 发散：尚未认真试过的理论角度

1. **模块化障碍（m=37 是素数 → F₃₇² 帽集）**
   rot4 的 148 点模 37 投影到 F₃₇²，NTIL 要求投影集无 3 点共线。F_p² 中这种集合
   有 caps / 广义四边形上界——可能给出存在性障碍或构造提示。完全没碰过。

2. **FD 连续松弛 + 取整引理**
   148 点在圆盘里最小化共线三元组（势能排斥）。用户之前"两解平均近似 NTIL"的直觉
   指向——解空间可能是个流形，连续优化后取整/舍入可能掉进整数解。
   值得认真做"平均 → 最近整数网格 → 局部修正"流水线。

3. **2-因子 Cayley 图连通性**
   以允许 2-交换为生成元，在 2-因子空间上建 Cayley 图。观察 4 个 v40 解是否同连通
   分量、0 解是否"可达"——可能暴露一直用错类型的 move（如需要 6-圈 3-交换而非
   4-圈 2-交换）。

4. **共线条件的纯代数刻画**
   三个 FD 单元 + 3 个取向比特的共线 = 行列式 0。rot4 下 64 个提升组合落入轨道，
   能否把"该三元组可共线"化简为一个关于 (a,b,c,d,e,f) 和 3 比特的双线性型？
   这是把 SIRH 二次层变成可计算符号的下一步。

5. **修正后重测匹配壳层**（最高杠杆的即时步骤）
   把正确 oracle 套进已有壳层脚本，看 56 的墙是否塌掉。若塌掉，m=37 比以为的可攻。

## 4. 下一步（按性价比，待 v40 复核结果后定）
